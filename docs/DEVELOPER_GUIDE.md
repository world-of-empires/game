# Руководство разработчика — WorldOfEmpires

**Начни с этого файла.** Здесь всё, что нужно новому разработчику: как устроен проект, как работать с кодом и как правильно фиксировать изменения.

---

## 1. О проекте

- **Платформа:** Unreal Engine 5.7
- **Язык:** C++
- **Структура:** модуль WorldOfEmpires, Core (GameMode, GameState, PlayerState)

## 3. Быстрый старт

1. Открой проект в Unreal Editor 5.7
2. Убедись, что GameMode в World Settings установлен на **WoE_GameMode**
3. Запусти игру (Play) — в Output Log должно появиться «WoEGameMode: BeginPlay вызван»

## 4. Архитектура (кратко)

```
Source/WorldOfEmpires/
├── Core/           → GameMode, GameState, PlayerState, Character
├── WorldOfEmpires.Build.cs  → Зависимости модуля
└── WorldOfEmpires.cpp      → Регистрация модуля
```

**Правило:** Новые классы — в `Core/` с префиксом `WoE_`.

**Камера:** AWoE_Character использует top-down камеру (King's Bounty) с переключением на First Person. Boom управляется через `SetWorldRotation` (не controller rotation). Подробности: AI_CONTEXT.md § 2.4.

Подробности: **ARCHITECTURE.md**

## 5. Как вносить изменения

### 5.1. Перед началом

- Прочитай **ARCHITECTURE.md** — куда класть файлы, как именовать
- Открой **AI_CONTEXT.md** — какие классы уже есть, чтобы не дублировать

### 5.2. Именование

- **Префикс WoE_** для всех классов проекта
- **Файлы:** `WoE_<ИмяКласса>.h` / `WoE_<ИмяКласса>.cpp`
- **Actor:** префикс A (AWoE_GameMode)

### 5.3. Репликация

- Для сетевых свойств: `UPROPERTY(Replicated)` + `GetLifetimeReplicatedProps` + `DOREPLIFETIME`

## 6. Как правильно зафиксировать изменения

После того как код готов, выполни по порядку.

### Шаг 1: Проверка кода

- [ ] Проект компилируется (Build в Editor или через UBT)
- [ ] Игра запускается без крашей
- [ ] Соответствие ARCHITECTURE.md (префиксы, структура)

### Шаг 2: Документация

| Что изменил | Что обновить |
|-------------|--------------|
| Новый класс, свойство, функция | **AI_CONTEXT.md** — добавить в таблицу |
| Изменил API | **AI_CONTEXT.md** — обновить строку |
| Удалил класс/экспорт | **AI_CONTEXT.md** — удалить строку |
| Новая папка, новые правила | **ARCHITECTURE.md** |
| Только внутренний рефакторинг | Документацию можно не трогать |

### Шаг 3: CHANGELOG

Добавь запись в начало **CHANGELOG.md**:

```markdown
## [X.Y.Z] — ДД.ММ.ГГГГ

**Краткое описание** | Что сделано

### Добавлено / Изменено / Исправлено

- **путь/к/файлу** — что изменилось
```

### Шаг 4: Версия

Обнови **VERSION** (одна строка: `X.Y.Z`):

- **PATCH** (0.0.1 → 0.0.2): исправления, рефакторинг, правки документации
- **MINOR** (0.0.1 → 0.1.0): новая функциональность, новые классы
- **MAJOR** (0.0.1 → 1.0.0): breaking changes

### Шаг 5: Версия в документах

- **AI_CONTEXT.md** — в конце: `*Документ актуален для версии X.Y.Z*`
- **ROADMAP.md** — «Текущая версия» и таблица (если нужно)

### Шаг 6: Коммит

```bash
git add -A
git status
git commit -m "vX.Y.Z: Краткое описание

- Деталь 1
- Деталь 2"
```

## 7. Автоматическая финализация (промпт для ИИ)

После завершения разработки скопируй промпт из **PROMPT_FINALIZE.md** и вставь в чат с ИИ. ИИ автоматически:

- проанализирует изменения (git status)
- определит тип версии (patch/minor/major)
- обновит CHANGELOG, ROADMAP, AI_CONTEXT, VERSION
- создаст git commit

---

## 8. Памятка (кратко)

```
Код готов
    ↓
Обнови AI_CONTEXT (если новый/изменённый API)
    ↓
Добавь запись в CHANGELOG
    ↓
Подними версию в VERSION
    ↓
Обнови версию в AI_CONTEXT, ROADMAP
    ↓
git add → commit
```

**Добавил новый код → обнови AI_CONTEXT.md.**  
**Поменял структуру проекта → обнови ARCHITECTURE.md.**

## 9. Работа с ИИ

При генерации кода через ИИ прикрепляй:

- **ARCHITECTURE.md** — правила и структура
- **AI_CONTEXT.md** — что уже реализовано

Промпт-шаблон:

```
Проект: WorldOfEmpires (Unreal Engine 5.7).
Архитектура: ARCHITECTURE.md
Реализованный код: AI_CONTEXT.md

Задача: [описание]

Учитывай существующие классы, не дублируй код, следуй префиксу WoE_.
```
