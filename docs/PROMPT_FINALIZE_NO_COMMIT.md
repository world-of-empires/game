# Промпт для финализации (без commit)

**Вариант 2:** обновление документации и версии, но **без выполнения git commit**. ИИ выведет готовый текст для commit — скопируешь и сделаешь вручную.

**Как использовать:** скопируй весь текст из блока ниже (от `---` до `---`) и вставь в чат с ИИ.

---

Ты — финализатор изменений в проекте WorldOfEmpires (Unreal Engine 5.7). Выполни следующие шаги **автоматически, без вопросов**.

**Режим:** обновляй документацию и версию, но **НЕ выполняй git commit**. В конце выведи готовый текст для commit.

## Контекст проекта

- **Структура:** `Source/WorldOfEmpires/Core/` — игровая логика (GameMode, GameState, PlayerState)
- **Правила:** префикс WoE_ для классов, файлы WoE_<Имя>.h/cpp
- **Документы:** `docs/ARCHITECTURE.md`, `docs/AI_CONTEXT.md`, `docs/CHANGELOG.md`, `docs/ROADMAP.md`, `docs/DEVELOPER_GUIDE.md`
- **Версия:** хранится в файле `docs/VERSION` (одна строка: X.Y.Z)

## Задача

1. **Проанализируй все изменения** — выполни `git status` и прочитай изменённые/новые/удалённые файлы. Пойми, что было добавлено, изменено, удалено.

2. **Проверь и синхронизируй архитектуру:**
   - Получи актуальную структуру проекта: перечисли все папки и файлы в `Source/WorldOfEmpires/` (рекурсивно)
   - Сравни с тем, что описано в **docs/ARCHITECTURE.md** (разделы «Структура каталогов», «Разделение слоёв», «Куда помещать файлы»)
   - Если структура изменилась — обнови docs/ARCHITECTURE.md:
     - Добавь новые папки в дерево каталогов и в таблицу слоёв
     - Добавь новые типы файлов в «Куда помещать файлы» (по фактическому расположению)
     - Обнови раздел «Зависимости модуля», если изменился WorldOfEmpires.Build.cs
   - Выполняй эту проверку **каждый раз** при финализации — архитектура должна всегда соответствовать реальному проекту

3. **Определи тип версии автоматически:**
   - **PATCH** (0.0.1 → 0.0.2): исправления багов, рефакторинг, правки документации, мелкие правки, обновление комментариев
   - **MINOR** (0.0.1 → 0.1.0): новая функциональность, новые классы, новые свойства/методы, новые файлы исходного кода
   - **MAJOR** (0.0.1 → 1.0.0): breaking changes (меняются публичные API несовместимо, удаление классов/свойств)

4. **Обнови документацию:**
   - **docs/CHANGELOG.md** — добавь в начало новую версию с датой (ДД.ММ.ГГГГ), кратким описанием и списком изменений по разделам:
     - ### Добавлено — новые файлы, новые классы, новые свойства
     - ### Изменено — изменённые файлы с описанием
     - ### Удалено — удалённые файлы
     - ### Исправлено — багфиксы
   - **docs/ROADMAP.md** — обнови «Текущая версия» и «Последнее обновление», добавь строку в таблицу «Сводка по версиям и фазам» если была новая функциональность
   - **docs/AI_CONTEXT.md** — если появились новые классы/свойства/методы: добавь в соответствующий раздел. Если удалены — удали. Обнови версию в конце: `*Документ актуален для версии X.Y.Z*`
   - **docs/ARCHITECTURE.md** — уже обновлён на шаге 2. Если были изменения — добавь в CHANGELOG запись «docs/ARCHITECTURE.md — синхронизация со структурой проекта»

5. **Обнови версию:**
   - В файле `docs/VERSION` — замени содержимое на новую версию (X.Y.Z)
   - В конце docs/AI_CONTEXT.md: `*Документ актуален для версии X.Y.Z*`
   - В docs/DEVELOPER_GUIDE.md (в конце): `*Версия руководства: X.Y.Z*`

6. **Выведи готовый текст для commit** — **НЕ выполняй** `git add` и `git commit`. Вместо этого выведи в ответе блок с **подробным** сообщением коммита.

**Формат commit-сообщения (подробный):**
- Первая строка: `vX.Y.Z: Краткое описание` (до 72 символов)
- Пустая строка
- Раздел **Добавлено:** — каждый новый файл с кратким описанием что в нём (класс, функции, назначение)
- Раздел **Изменено:** — каждый изменённый файл с описанием что изменилось
- Раздел **Удалено:** — если были удаления
- Раздел **Документация:** — перечень обновлённых docs/* с указанием что обновлено

Каждый пункт — отдельная строка с отступом `- `. Описание должно быть конкретным (не «обновление», а «добавлен WoE_Character в структуру каталогов»).

```
--- Текст для commit (скопируй и выполни вручную) ---

git add -A
git commit -m "vX.Y.Z: Краткое описание

Добавлено:
- путь/к/файлу — описание (класс, функции, назначение)

Изменено:
- путь/к/файлу — что изменилось

Документация:
- docs/CHANGELOG.md — запись vX.Y.Z
- docs/ROADMAP.md — версия, таблица
- docs/AI_CONTEXT.md — новый раздел / обновление
- docs/ARCHITECTURE.md — структура каталогов
- docs/VERSION — X.Y.Z"

---
```

## Формат CHANGELOG

```markdown
## [X.Y.Z] — ДД.ММ.ГГГГ

**Краткое описание** | Тип изменений

### Добавлено

- **Source/WorldOfEmpires/Core/WoE_Example.h** — описание

### Изменено

- **Source/WorldOfEmpires/Core/WoE_GameMode.cpp** — описание

### Удалено

- **путь/к/файлу** — описание

### Исправлено

- **путь/к/файлу** — описание
```

## Важно

- Действуй автоматически. Не спрашивай «какую версию выбрать» — определи по типу изменений.
- **НЕ выполняй** `git add`, `git commit`, `git push` — только выведи текст для commit.
- Если изменений нет (git status пустой, только незакоммиченные правки документации) — сообщи об этом и не обновляй версию без явного запроса.
- Используй сегодняшнюю дату в формате ДД.ММ.ГГГГ.
- Игнорируй изменения в папках `Intermediate/`, `Saved/`, `DerivedDataCache/`, `.vs/` — они не входят в коммит.
- Файлы документации (ROADMAP, CHANGELOG, AI_CONTEXT и т.д.) — при их обновлении как часть финализации используй PATCH, если нет других изменений кода.

Выполни все шаги по порядку.
