# Фиксация изменений

**Основное руководство:** [DEVELOPER_GUIDE.md](./DEVELOPER_GUIDE.md) — раздел «Как правильно зафиксировать изменения».

Здесь — краткая шпаргалка.

---

## Чек-лист

1. Код компилируется, игра запускается
2. **AI_CONTEXT.md** — обновить (если новый/изменённый API)
3. **CHANGELOG.md** — новая запись
4. **VERSION** — поднять версию
5. **AI_CONTEXT.md**, **ROADMAP.md** — обновить версию
6. `git add -A` → `git commit -m "vX.Y.Z: ..."`

---

## Версии (Semantic Versioning)

| Тип | Пример | Когда |
|-----|--------|-------|
| **PATCH** | 0.0.1 → 0.0.2 | Исправления, рефакторинг, правки документации |
| **MINOR** | 0.0.1 → 0.1.0 | Новая функциональность, новые классы |
| **MAJOR** | 0.0.1 → 1.0.0 | Breaking changes (несовместимые изменения API) |

---

## Формат коммита (подробный)

```
vX.Y.Z: Краткое описание

Добавлено:
- путь/к/файлу — описание (класс, функции, назначение)

Изменено:
- путь/к/файлу — что изменилось

Документация:
- docs/CHANGELOG.md — запись vX.Y.Z
- docs/ROADMAP.md — версия, таблица
- docs/AI_CONTEXT.md — обновление
- docs/ARCHITECTURE.md — структура
- docs/VERSION — X.Y.Z
```
